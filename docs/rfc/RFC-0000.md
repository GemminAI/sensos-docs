## Abstract

RFC-0000 is the constitutional governance document of the GemminAI / SensOS RFC ecosystem. It defines **only** what no single series can decide for itself:

- authority hierarchy (procedural, not technical)
- RFC series registry
- shared number and naming spaces
- versioning policy
- constitutional-compliance requirement
- amendment procedure

It owns no mathematics, runtime behavior, type system, or knowledge model. Domain constitutions remain sovereign over their technical content.

## Specification

### 1. Authority hierarchy

```text
RFC-0000  (ecosystem governance)
    │
    ├─► Series constitutions (e.g. SensOS / NVS, NOMOS, STS, DAK, …)
    │       (sovereign over domain technical content)
    │
    └─► Individual series RFCs
            (MUST satisfy series constitution + RFC-0000 procedural rules)
```

**Rules**

- If a subordinate RFC’s **governance behavior** conflicts with RFC-0000, **RFC-0000 SHALL prevail**.
- Cross-series **technical** conflicts are escalated via governance procedure; RFC-0000 does not adjudicate domain mathematics.
- Intra-series conflicts with a series constitution are resolved inside that series.

### 2. Constitutional compliance (required section)

Every normative RFC SHALL include a Constitutional Compliance section with:

1. Applicable constitutional principles (from its own series constitution)
2. Normative references
3. Responsibility boundary statement

### 3. Series registry (portal view)

| Series | Responsibility band | Notes |
|---|---|---|
| RFC-NVP / NOMOS | Physics | Field / TAG foundations |

| RFC-NVS-DAK | Semantic Runtime | Dynamic Abort / safety |
| HEKB | Semantic Runtime (narrowed) | Constraint boundary in product scope |
| AIIE | Bridge | Physics → Semantic Runtime |
| Applications | Applications | Outside this portal’s core |

### 4. Versioning policy

| Change class | Version impact |
|---|---|
| Breaking architecture / ABI / constitutional principles | Major |
| Non-breaking refinement, new compatible sections | Minor |
| Editorial only | Patch |

Historical published versions SHALL remain permanently accessible and MUST NOT be overwritten.

### 5. Naming collisions

Cross-series term collisions (e.g. multiple historical meanings of “DAK”) MUST be registered for visibility. Renaming remains each series’ editorial choice; silent collision is forbidden.
