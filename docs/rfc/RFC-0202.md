# RFC-0202: Runtime Bridge

| Field | Value |
|---|---|
| **Status** | Draft |
| **Version** | 1.0.0 |
| **Last Updated** | 2026-07-26 |
| **Series** | Runtime ABI (portal 02xx) |
| **Provenance** | Portal synthesis of Runtime Bridge patterns (annotation isolation; SA-Real / bridge lineage) |

## Abstract

Defines the **Runtime Bridge**: the isolation boundary that confines non-deterministic annotation (or similarly non-reproducible) calls so that Observation and Projection contracts remain reviewable and testable.

The Bridge is a *category of concern*, not a mandate for a specific transport (in-process protocol vs HTTP). Implementations MUST document which transport class they use.

## Specification

### 1. Problem

Annotation may involve models or services that are:

- non-deterministic across runs
- latency-variable
- failure-prone

If these properties leak into ProjectionProvider inputs without control, RFC-0100 verification and CORE conformance become ill-defined.

### 2. Bridge responsibilities

A Runtime Bridge **MUST**:

1. Present a narrow interface to the Observation Layer for “request annotation / receive annotation”
2. Record enough provenance (model id, prompt/hash, timestamps, error class) for audit
3. Allow annotation freeze (persist annotation bytes) for reproducible projection tests

A Runtime Bridge **SHOULD**:

1. Timeout and error-map failures into typed Observation Layer errors
2. Avoid baking Meaning Firewall policy into the transport layer

A Runtime Bridge **MUST NOT**:

1. Become a second Observation ABI
2. Bypass `AnnotatedObservation` as the Projection handoff

### 3. Transport classes

| Class | Description | Notes |
|---|---|---|
| In-process | Protocol object inside one runtime | Preferred for local CORE |
| RPC / HTTP | Out-of-process annotator | Must document auth & retry policy separately |
| Batch / offline | Precomputed annotations | Valid for verification corpora |

### 4. Interaction with RFCs

```text
Observation Layer (RFC-0200)
        │  annotate()
        ▼
 Runtime Bridge (this RFC) ──► Annotator implementation (non-normative)
        │
        ▼

```
