## Abstract

Defines the **product-normative** role of HEKB inside SensOS:

> HEKB is a **ConstraintStore / Boundary Oracle** — the holder of constraint and boundary definitions used by runtime evaluation — **not** a broad general-intelligence world-model knowledge base.

This RFC exists so architecture, conformance, and research tracks cannot silently revive superseded broad-HEKB product claims.

## Specification

### 1. Normative role

HEKB (product scope) **MUST** be treated as:

1. A store of **boundary / constraint definitions**
2. An oracle consulted during navigation / risk evaluation
3. A component that refuses ownership of customer application domain knowledge

HEKB (product scope) **MUST NOT**:

1. Be required as an open-world encyclopedic KB for CORE conformance
2. Override Observation or Projection ABIs
3. Be cited as proof of general intelligence capability

### 2. Interface intent

```text
Projection / Kernel trajectory state
            │
            ▼
   ConstraintStore.evaluate(state, policy) -> { allow | deny | constrain, evidence }
            │
            ▼
   Runtime intervention / logging (DAK / safety companions)
```

Exact method names evolve with Implemented releases; the responsibility boundary does not.

Historical SensOS materials narrowed HEKB from “heterogeneous knowledge base” to ConstraintStore. This portal RFC **reaffirms that narrowing** as Accepted product law for documentation SSOT.
